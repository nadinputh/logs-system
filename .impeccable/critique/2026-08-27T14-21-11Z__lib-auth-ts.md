## Priority Issues

### [P0] No session revocation, no session inventory, no "sign out all devices"
JWT strategy + 30-day default + no denylist = lost phone stays signed in as admin for 30 days. Only server-side kill switch is rotating `NEXTAUTH_SECRET` (nukes every user). Fix: `User.sessionsVersion`, stamp in JWT, re-check on `jwt` callback via short cache; ship "Sign out other devices" control.

### [P0] `/terminal` middleware guards the wrong role
Middleware: `token.role === "admin"` (system). API: `terminal.scan` → team `manager+`. Every self-signup team owner (default `staff`) is locked out of their own kiosk at the page level; system-admin users without team `manager` get the page but 403'd by API. Fix: remove middleware branch, add `app/terminal/layout.tsx` guarding via `requireTeamPageAccess("manager", "/terminal")`.

### [P1] Middleware coverage is a hint, not a fence
`/settings` matcher exists but `app/settings/layout.tsx` has no `requireTeamPageAccess`. `/profile` is in matcher but has no page-guard. Contract is scattered.

### [P1] Suspension has no user-visible message; deleted team leaves stale activeTeamId
`requireTeamPageAccess` uses same redirect for both "no active team" and "you are not a member". A suspended user is indistinguishable from a first-timer. Removal never clears the target's `activeTeamId` — silent redirect dance.

### [P1] App-owned POST/PATCH/DELETE routes have no CSRF check beyond sameSite=lax
NextAuth's own routes ship double-submit CSRF cookie. The app's routes rely only on `sameSite=lax`. Fix: shared `Origin` header assertion.

### [P2] `POST /api/logs` silently ignores its own auth error
Distinguish "no session" from "session but forbidden".

## What's Working
1. DB re-derivation over JWT trust for team decisions — `requireTeamAccess` always re-fetches `TeamMember.status="active"`.
2. Permission-to-role map centralized and small (`lib/teamPermissions.ts:1-45`).
3. Passkey pre-auth token uses `findOneAndDelete` for atomic one-use redemption.

- Passkey pre-auth token binds only `userId` — no IP/UA fingerprint.
